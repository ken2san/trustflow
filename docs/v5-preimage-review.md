# Canonical v5 event preimage review

**Recommendation:** adopt T126's 13 ordered keys, with the strict input rules below. Use v5 only for delegated events. Keep the credential ID and issuer kind in the event preimage itself and leave the action payload's existing meaning intact. This is a review proposal pending Kenji's confirmation of the representation and v5 input rules. Row 3 remains open and this proposal does not enable a writer.

## Exact proposal

Construct a fresh object with these keys in order. Hash the UTF-8 bytes of its compact ECMAScript `JSON.stringify` output, without a BOM, newline, pretty printing, whitespace between tokens, or a replacer. Return lowercase SHA-256 hex.

| # | Key | Value |
|---|---|---|
| 1 | `domain` | Fixed JSON string `"trustflow.event"` |
| 2 | `hash_version` | JSON integer `5`, unquoted |
| 3 | `id` | Event UUID |
| 4 | `type` | Event type string |
| 5 | `contract_id` | Deal UUID |
| 6 | `actor_id` | Verified issuer account UUID |
| 7 | `dod_hash` | SHA-256 of the event's recorded criteria under the existing DoD encoding |
| 8 | `created_at` | UTC date-time string with exactly three fractional digits and trailing `Z` |
| 9 | `prev_hash` | Stored `prev_event_hash`, SHA-256 hex or the exact string `"GENESIS"` |
| 10 | `payload_hash` | SHA-256 of the full recorded action payload under the existing payload encoding |
| 11 | `agreement_hash` | SHA-256 of the agreement snapshot under its established snapshot version, or JSON `null` when no accepted snapshot exists |
| 12 | `credential_id` | Nonsecret grant UUID |
| 13 | `issuer_kind` | Exactly `"owner_account"` or `"counterpart_account"` |

- **Presence and typing.** Every key is emitted exactly once. Require each row/export input as an own property, including an explicit numeric `hash_version` and explicit `agreement_hash`. The domain is supplied by the v5 format. If a transport includes it, require the exact constant. Missing and `undefined` fail validation. No empty string, zero, stringified number or omitted key substitutes for null or a digest. The only nullable value is `agreement_hash`. All hashes must match `^[0-9a-f]{64}$`. UUID strings use lowercase hex, hyphens in 8-4-4-4-12 layout and no surrounding characters. No case folding or trimming. Event type is a nonempty ASCII dotted identifier whose segments start with `a–z` and continue with `a–z`, digits or underscore. Writers additionally require a registered event type with the scope to write it.
- **Timestamp.** Writers use a finite, valid UTC instant at exact millisecond precision. Readback may be a Gregorian date-time with a four-digit year (0001–9999), uppercase `T`, seconds 00–59, optional 1–6 fractional digits, and `Z` or an explicit numeric `±HH:MM` offset (hours 00–23, minutes 00–59, excluding `-00:00`). Require a real calendar day and time, including hours 00–23. Fractional digits after the third must be zero. Convert the instant to UTC within the same supported year range and pad to three digits. For example, `2026-01-02T04:04:06.123000+01:00` becomes `2026-01-02T03:04:06.123Z`. Reject invalid or timezone-less values and nonzero submillisecond precision. The v4 permissive timestamp fallback and truncation remain legacy behavior only.
- **Strings and numbers.** Use ECMAScript JSON escaping, including backslash and control-character escaping, and UTF-8 for Unicode. Preserve code points without normalization and reject unpaired surrogates in v5 text. The only number in the outer object is `5`. The existing separate DoD/payload/snapshot digest encodings use recursive key sorting by UTF-16 code units, ECMAScript compact JSON scalar and number serialization and unchanged array order. Producers supply JSON values, with finite ECMAScript numbers and no undefined members. Zero and negative zero serialize as `0`. Do not introduce alternate decimal, locale or database text encodings. Recompute from stored JSON-compatible values and test round-trip parity for the supported payloads. A known empty object hashes as `{}`, distinct from a missing payload. A reader given only a guest projection can recompute the outer event hash from the recorded `payload_hash`, but cannot generally recompute that digest from the projection.
- **Chain and missing inputs.** A writer explicitly stores `GENESIS` only for the first hashed link of the deal under existing chain rules. It stores the previous event's digest otherwise, even across versions. A v5 verifier never turns null or missing predecessor data into `GENESIS`. A sliced or truncated view cannot establish a whole chain. Absent or malformed canonical inputs are unverified/invalid input. A different digest with valid complete inputs is a mismatch. Unsupported versions stay unsupported. Retain legacy v1/v2 inference only where the legacy contract permits it. Explicit v5 or a row carrying v5 authority fields cannot fall back to a legacy version when malformed.
- **Agreement coverage.** Before acceptance, require an explicit null `agreement_hash`. Keep the DoD digest, which does not bind price, deadline or a full agreed snapshot. Acceptance itself binds the snapshot it atomically creates. Later acts derive the agreement hash from the current terms using the recorded accepted snapshot version, preserving the existing ability to detect terms drift. Refuse to write if a snapshot/version is expected but missing or unsupported. Coverage labels must depend on the recorded digest and available content, rather than the version number alone.

### Authority and source of truth

Store `credential_id` and `issuer_kind` once as typed, immutable event fields, and project those fields into the final two top-level canonical keys. Reject caller-supplied authority at the write boundary. Reserve those authority names in the action payload and do not maintain a competing payload copy. Guest canonical blocks and both exports may expose the approved nonsecret values from the same fields under existing deal access controls. Never export a grant secret or its verifier. The server must derive both values while checking the live grant, exact deal, issuer account and role, scope, expiry and revoke status under the writer's lock. The digest cannot independently prove who operated the account, when the server observed the act or whether the grant check was performed honestly.

The top-level choice interprets C2's “canonical payload” as the bytes given to the event hash. `Decisions.md:47` uses that wording, and `docs/entry-contract.md:20` says “canonical payload/hash”. If either means specifically the stored action `payload`, this proposal needs an explicit owner decision. Nesting the authority there would couple guest recomputation to a payload projection that intentionally hides internal keys. Storing both would require two representations to agree forever. Confirm the top-level interpretation before freezing v5.

## Review evidence and risks

- `supabase/functions/_shared/eventCanonical.ts:39–61,218–337` preserves distinct legacy versions and refuses unknown ones. Keep v1–v4 outputs and the public v4 vector unchanged. Add an explicit v5 branch and keep the ordinary writer default at v4. Shared hashing code, the row's hash version, the receipt envelope version and the accepted snapshot version are separate concepts.
- `supabase/functions/_shared/eventRecord.ts:253–293` derives current criteria, agreement and payload digests and uses the current write version. Do not globally change that version or accidentally carry the v4 unconditional agreement digest into a v5 pre-acceptance record.
- `guest-contract-events/index.ts:202` selects specific columns. `guestEventView.ts:132–165` presently fills nulls and infers versions while shaping. Validate v5 source fields before that step. Update the canonical key lists, `src/lib/eventFormat.js` coverage and unverifiable states, and the owner/guest export pipelines (`auditExport.js`, `guestRecordExport.js`). A v5-only addition to the encoder does not make missing output fields appear.
- `scripts/make-receipt.mjs` and `scripts/verify-chain.mjs` use explicit DB select lists. `scripts/verify-receipt.mjs:75–125` also enumerates required canonical inputs and expects an agreement snapshot. Use per-version requirements so legacy receipts continue to verify without authority fields. In a mixed receipt, mark the snapshot check inapplicable for a pre-acceptance v5 row with a null digest. A draft-only file must report no accepted agreement rather than synthesizing a snapshot or a successful agreement verification. Ensure an unsupported or incomplete v5 row cannot turn into a successful chain verdict by skipping it or verifying only a suffix. Replace stale v1–v4 verification instructions alongside reference vectors in the public protocol and emitted exports. The `make-receipt.mjs:16–24` comment calls future salted commitments “v5”. That name conflicts with decided C2. Selective disclosure of payload commitments remains separate work.
- SQL is the atomic persistence boundary, not a second event encoder. `20260928000000_atomic_acceptance.sql:12–18` explains why Deno computes event hashes. Current acceptance and guest append SQL compare the tip and insert supplied evidence using `jsonb_populate_record` (`20261110150000_accept_writes_snapshot_version.sql:158–218`, `20261114120000_guest_append_under_credential_lock.sql:260–282`). PostgreSQL can ignore JSON members absent from the row type. Writer-first deployment could commit a hash whose authority inputs were silently lost. Require schema and version-aware persistence checks plus round-trip tests before any writer enablement. Do not serialize `jsonb::text` to reconstruct event bytes. The credential migration's SHA-256 at `20261118214020_entry_agent_credentials.sql:117` checks the invite, not an event hash.
- A correct chain may run v4 → v5 → v4. Test ordinary append, reissue and acceptance across the boundary with real stored predecessors and accepted snapshot versions. Existing owner replay checks compare type and actor alongside the key (`log-event/index.ts:359–386,638–681`). A delegated replay also needs the bound grant/issuer context. A same-account ordinary path must not replay a delegated event or accept an unbound fallback. Test both legacy and delegated collision/retry paths before enabling v5.
- After the first v5 row, field names, byte order, timestamp precision and authority semantics are permanent for that version. Keep immutable rows and grant evidence. Roll back by disabling the v5 writer or deploying compatible readers and writers. Never downconvert, drop authority columns still needed by rows, rehash history, or roll readers back to a build that cannot verify v5. Offline copies of older verifiers remain limited and must fail closed. Distinguish a recomputed row hash, a complete linked chain, payload verification, and actual authority.
