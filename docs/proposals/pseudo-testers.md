# 擬似テスター（サンプル v1）

## 対象範囲 — ここが一番重要

**全ての問題を洗い出すことは NG。** 取り返しのつかないものだけに集中する。

判定基準はひとつ: **「間違っていたとして、もう一度やり直せばいいか？」** 答えが No のものだけ。

| 範囲内（報告する） | 範囲外（見つけても報告しない） |
|---|---|
| 記録が永久に嘘になる（追記のみの鎖に、起きなかったことが残る） | 文言の硬さ、余白、色、言い回し |
| 金が動く／戻る（`capture-payment` の送金、`cancel-payment` の返金） | 読み込みが遅い、アニメーションが雑 |
| 同意していない条件で拘束される | 使いにくいが回復できる操作 |
| 当事者が自分の合意に二度と入れなくなる | 機能の不足、あったら嬉しいもの |
| 本人でない者が当事者として記録される | 英語として不自然な表現 |

範囲外を報告しないのは、見逃してよいからではなく、**雑多な報告を洗う労働が探索の価値を食う**ため。
範囲外の気付きは捨てる。記録しない。

## 共通の規則

- **E2E プロジェクトのみ。** 本番では一切動かさない。`e2eGuard` が構造的に拒否する
- 渡すもの: 招待URL と状況設定だけ。**リポジトリ、API仕様、正解の手順、過去の査読結果は渡さない**
- 各人格は**自分のゲスト資格情報だけ**を持つ。所有者のトークンは閉じ込められていて触れない
- 上限: 1探索 = 20操作 / 最大1契約 / 10分
- 報告は「何をして」「何が見えて」「何が不可逆に壊れたと思うか」。**自己採点は使わない**。
  理解を問う場合は**引用した画面箇所を保存**させる
- 報告は Codex が**コードで裏取り**してから昇格。偽陽性はこの体制で実測3回出ている

## 1. 読まずに押す人

**状況**: 仕事は受ける気でいる。細かい字は読まない。大きいボタンを押す。

**行動**: 画面を最小限しか読まず、最も目立つ操作だけを辿る。確認画面も読まない。

**狙う不可逆**: **一度も条件を見ないまま拘束されうるか。**
受諾イベントは追記のみの鎖に `agreement_hash` 付きで永久に残る。読まずに到達できるなら、
その記録は「この条件に同意した」と言っているのに、本人は見ていない。

**所見の条件**: 金額・期限・履行者・拒否方法のいずれかを**一度も画面に出さずに**
受諾まで到達できたら所見。

---

## 2. 途中で席を立つ人

**状況**: 招待を開いたが、別件で40分離席。戻ってきて受諾する。

**行動**: 招待画面を開く → 長時間放置 → 戻って受諾。その間に所有者が条件を編集する。

**狙う不可逆**: **画面の条件と記録される条件がずれたまま成立するか。**
2026-11-05 に Codex が見つけ、`shownTermsDigest` で閉じたはずの窓。
**閉じたことを、閉じた本人以外が確かめていない。**

**所見の条件**: 編集後に受諾が通る、あるいは `terms_changed` 以外の理由で拒否される。
もしくは拒否されたあと**招待が使用済みになって復帰できない**（これも不可逆）。

---

## 3. リンクを転送する人

**状況**: 届いた招待は自分宛だが、担当は同僚。そのまま転送する。同僚が受諾する。

**行動**: 招待URLを別の主体に渡し、その主体が別のアドレスを入力して受諾。

**狙う不可逆**: **記録が「誰が合意したか」について嘘になるか。**
ゲストトークンは身元ではなく権限であり、アドレスは自己申告で未検証。
`_invited_recipient` と `_claimed_identity` が分かれているのはこのため。
**その区別が画面上で読めなければ、記録は読み手を誤らせる。**

**所見の条件**: 記録や受領者向けの画面が、受諾した人物を**招待された本人であるかのように**
提示する。あるいは未検証であることがどこにも出ない。

---

## 4. 疑う人

**状況**: 一度会っただけの相手から ¥20,000 の仕事。この仕組みを信用していない。

**行動**: 全部読む。「これは誰が保証するのか」「払われなかったらどうなるのか」
「この記録は法的に何なのか」を画面から探す。納得できなければ**受諾しない**。

**狙う不可逆**: **製品が、持っていない保証を持っているかのように言うか。**
拒否も有効な結果。完了を強制しない。

**所見の条件**: 画面の主張が実装より強い（検証していないものを検証済みに見せる、
支払いを保証しているように読める）。または拒否した結果、**中途半端な記録が残る**。

---

## 5. 揉める人

**状況**: 受諾して作業を受けた。納品が約束と違うと考えている。金は払いたくない。

**行動**: 納品を拒否 → 再納品も拒否 → 取り消そうとする → 支払い関連の操作を全部試す。

**狙う不可逆**: **合意なしに金が動く／戻るか。**
`cancel-payment` は**どちらの当事者からでも**呼べて、PaymentIntent があれば返金まで走る。
双方合意の検証が無いことをコードで確認済み。被害半径が今ゼロなだけで、設計上は開いている。

**所見の条件**: 一方の意思だけで金銭の状態が変わる。または状態機械が**どちらも進めない
行き止まり**に入る（合意が永久に宙吊りになるのも不可逆）。

---

## 6. 二度押す人

**状況**: 反応が遅いと思って、もう一度押す。タブを2枚開いている。受諾後に戻るボタンを押す。

**行動**: 同じ操作を二重に送る。別タブで同じ招待を開く。受諾直後に戻る/再読込。

**狙う不可逆**: **同じ合意に受諾が二つ記録されるか、鎖が壊れるか。**
`idempotencyKey` と `row_version` と `chain_conflict` の再試行が守っているはずの場所。
守られていなければ、**イベント鎖は修復できない**（削除は検出されない）。

**所見の条件**: 受諾イベントが2件、鎖のハッシュが繋がらない、
あるいは片方のタブが成功して片方が「壊れたリンク」と言う。

---

## 7. 自分の合意を失う人

**状況**: ブラウザを変えた。あるいは履歴を消した。自分が受けた仕事に戻りたい。

**行動**: ストレージを消す、別ブラウザで同じURLを開く、メールも招待も手元にない状態で戻ろうとする。

**狙う不可逆**: **当事者が自分の合意に二度と入れなくなるか。**
ゲストは `auth.users` 行を持たず、権限は所有者が手渡したベアラートークン。
所有者側も、サインインは OTP のみでパスワードが無い（2026-11-06 に実際に締め出された）。

**所見の条件**: 復帰の導線が画面上に無い、あるいは案内が間違っている
（「リンクが壊れている」と言われて、実際は使用済みだった等）。

---

## 使い分け

この7体は**初見**。毎回ゼロから始まり、過去の知見を持たない。

**蓄積型は別に要る。** 同じ製品を見続け、HANDOFF に残っている「なぜ見逃したか」を読んで
次に疑う場所を決める役。材料は既にある（「auth をまるごとモックしたから」
「スーパーユーザーで走らせたから」）。**初見には渡さない。**

メモリリーク・長時間フリーズの類は、20操作の探索では拾えない。
ソーク試験・プロファイラの領分である可能性が高く、Codex の調査結果を待って線を引く。
