# 擬似テスター（サンプル v1）

## 対象範囲 — ここが一番重要

**全ての問題を洗い出すことは NG。** 取り返しのつかないものだけに集中する。

判定基準はひとつ: **「間違っていたとして、もう一度やり直せばいいか？」** 答えが No のものだけ。

**切り方はカテゴリではなく因果**。「文言だから捨てる」ではない。見た目の問題でも、
**条件が読めないせいで誤って承認する／誤った証拠が外に出る**なら中心リスク。
逆に、不可逆への経路が無い装飾の指摘は優先外。2026-11-06 の査読で、カテゴリ一律除外は
雑すぎると指摘されて直した。

**範囲内 — 記録専業の製品における不可逆:**

| | 具体例 |
|---|---|
| 誤った合意が永続する | 表示した金額/通貨/期限/履行者と snapshot が違う。古い表示のまま新条件を受諾 |
| 主体・権限の取り違え | 自分の申告が相手の受領確認として記録される。別契約のトークンで書ける。自己申告のアドレスが本人確認済みに見える |
| 不成立が成立として残る | 途中で失敗したのに受諾イベントだけ残る。招待だけ消費されて資格情報が渡らない |
| 履歴の欠落・分岐 | 受諾が二重に記録される。確定イベントが消える。鎖の順序が壊れる |
| 誤った証拠が外に出る | 不完全な export を完全と称する。読み取り失敗を0件と表示する。申告を検証済みの事実として提示する |
| 秘密・証拠の流出 | URL/トークン、他契約、非開示 payload が第三者に読まれる。**漏えいはやり直しで回収できない** |
| 証拠への恒久的アクセス喪失 | 再発行の競合で両方の資格情報が死ぬ。記録の取得・持ち出し経路が壊れる |
| 意味が後から書き換わる | 過去の当事者申告が、後の表示変更で客観的事実に格上げされる |

**範囲外**: 不可逆への因果経路が示せない指摘。言い回しの好み、余白、配色そのもの、
機能の不足、速度。**捨てる。記録しない。** 雑多な報告を洗う労働が探索の価値を食うため。

**当事者が嘘の申告をすること自体は欠陥ではない。** ハッシュ鎖は真実判定器ではなく、
申告を申告として正しく帰属させているなら仕様どおり（`Protocol.md:17-25`）。

## 共通の規則

- **E2E プロジェクトのみ。** 本番では一切動かさない。`e2eGuard` が構造的に拒否する
- 渡すもの: 招待URL と状況設定だけ。**リポジトリ、API仕様、正解の手順、過去の査読結果は渡さない**
- 各人格は**自分のゲスト資格情報だけ**を持つ。所有者のトークンは閉じ込められていて触れない
- 上限: 1探索 = 20操作 / 最大1契約 / 10分
- 報告は「何をして」「何が見えて」「何が不可逆に壊れたと思うか」。**自己採点は使わない**。
  理解を問う場合は**引用した画面箇所を保存**させる
- 報告は Codex が**コードで裏取り**してから昇格。偽陽性はこの体制で実測3回出ている

## 1. 読まずに押す人

**状況**: 仕事は受ける気でいる。細かい字は読まない。大きいボタンを押す。

**行動**: 画面を最小限しか読まず、最も目立つ操作だけを辿る。確認画面も読まない。

**狙う不可逆**: **重要な条件を提示しないまま承認させられるか。**
読まなかったこと自体は欠陥ではない — 人は読まない。欠陥は**製品が見せなかった**場合。
受諾イベントは `agreement_hash` 付きで永久に残り、「この条件に同意した」と言う。

**所見の条件**: 金額・通貨・期限・どちらが履行するか・拒否の方法のいずれかが
**承認に至る経路上に一度も表示されない**。表示されていて読まなかった場合は所見にしない。

---

## 2. 途中で席を立つ人

**状況**: 招待を開いたが、別件で40分離席。戻ってきて受諾する。

**行動**: 招待画面を開く → 長時間放置 → 戻って受諾。その間に所有者が条件を編集する。

**狙う不可逆**: **画面の条件と記録される条件がずれたまま成立するか。**
2026-11-05 に Codex が見つけ、`shownTermsDigest` で閉じたはずの窓。
**閉じたことを、閉じた本人以外が確かめていない。**

**所見の条件**: 編集後の受諾が**通ってしまう**（記録される条件 ≠ 見せた条件）。
または拒否された際に**状態が食い違う** — 招待が消費されたのに資格情報が渡らない、
受諾イベントだけ残る、復帰経路が無い。

拒否されること自体は所見ではない。期限切れ・取り消し・認証エラーも正当な拒否理由で、
`terms_changed` 以外なら欠陥という元の条件は広すぎた（2026-11-06 の査読で指摘）。

---

## 3. リンクを転送する人

**状況**: 届いた招待は自分宛だが、担当は同僚。そのまま転送する。同僚が受諾する。

**行動**: 招待URLを別の主体に渡し、その主体が別のアドレスを入力して受諾。

**狙う不可逆**: **記録が「誰が合意したか」について、持っていない確度を主張するか。**
転送できること自体は設計どおり — ゲストトークンは身元ではなく権限で、ベアラーモデルは
意図的。`_invited_recipient` と `_claimed_identity` が別フィールドなのもこのため。
欠陥は**その区別が読み手に届かない**場合。

**所見の条件**: 記録や受領者向け画面が、受諾者を**招待された本人として断定**する、
または自己申告のアドレスを**確認済みであるかのように**見せる。転送できたこと自体は所見にしない。

---

## 4. 疑う人

**状況**: 一度会っただけの相手から ¥20,000 の仕事。この仕組みを信用していない。

**行動**: 全部読む。「これは誰が保証するのか」「払われなかったらどうなるのか」
「この記録は法的に何なのか」を画面から探す。納得できなければ**受諾しない**。

**狙う不可逆**: **製品が、持っていない保証を持っているかのように言うか。**
拒否も有効な結果。完了を強制しない。

**所見の条件**: 画面の主張が実装より強い、を**具体的な虚偽として**特定できること:
承認していないのに承認済みと書く、支払いの申告しかないのに**入金確認**と書く、
自己申告のアドレスを本人確認済みと書く、ハッシュ鎖が**真実を証明する**と読める。

「中途半端な記録が残る」は曖昧なので取り下げ（2026-11-06 の査読で指摘）。
正当な途中経過と区別がつかない。拒否して何も記録されないのは正しい動作。

---

## 5. 揉める人

**状況**: 受諾して作業を受けた。納品が約束と違うと考えている。支払いたくない。

**行動**: 納品を拒否 → 再納品も拒否 → 支払いを争う（`payment.disputed`）→
相手が `payment.reported` だけ出した状態で記録を読む。

**狙う不可逆**: **双方の申告が消えるか、片側の主張が決着として表示されるか。**
照準を 2026-11-06 に変更した。元は「合意なしに金が動く」を狙っていたが、
**金は動かない**（決済は現行スコープ外）。記録製品にとっての不可逆は、
**争いの記録が失われること**と、**片側の申告が裁定や完了として読まれること**。

`Protocol.md:64-66` のとおり、拒否回数の上限も仲裁も存在しない。だから
「相手が答えない」「双方が合意しない」「取消ボタンが無い」は**欠陥ではない**。

**所見の条件**: 拒否や dispute の記録が後の表示に**出てこなくなる**。
`payment.reported` だけの状態が「支払い済み」と読める。最新の表示が過去の
`disputed` を**隠す**。不完全な export が現在の入金状態を**断定**する。

**別件として扱う既知の欠陥**: `cancel-payment` は片側の認可だけで `CANCELLED` に遷移し、
**イベントを1件も書かない**（`cancel-payment/index.ts:73-99`）。これは探索で見つける
対象ではなく、撤去対象として既に特定済み。Decisions.md の 2026-11-06 エントリを参照。

## 6. 二度押す人

**状況**: 反応が遅いと思って、もう一度押す。タブを2枚開いている。受諾後に戻るボタンを押す。

**行動**: 同じ操作を二重に送る。別タブで同じ招待を開く。受諾直後に戻る/再読込。

**狙う不可逆**: **同じ合意に受諾が二つ記録されるか、鎖が壊れるか。**
`idempotencyKey` と `row_version` と `chain_conflict` の再試行が守っているはずの場所。
守られていなければ、**イベント鎖は修復できない**（削除は検出されない）。

**所見の条件**: 受諾イベントが**2件記録される**、鎖のハッシュが繋がらない、
`trustpoints` やカウンタが二重に加算される。

片方のタブが成功して片方が失敗するのは**正常**（単回使用の招待なので当然）。
表示が食い違うだけでは所見にしない — 元の条件は広すぎた（2026-11-06 の査読で指摘）。

---

## 7. 自分の合意を失う人

**状況**: ブラウザを変えた。あるいは履歴を消した。自分が受けた仕事に戻りたい。

**行動**: ストレージを消す、別ブラウザで同じURLを開く、メールも招待も手元にない状態で戻ろうとする。

**狙う不可逆**: **当事者が自分の合意に二度と入れなくなるか。**
ゲストは `auth.users` 行を持たず、権限は所有者が手渡したベアラートークン。
所有者側も、サインインは OTP のみでパスワードが無い（2026-11-06 に実際に締め出された）。

**所見の条件**: **恒久的に**戻れない。既存の回復手段（所有者による再発行、
使用済み招待からの案内）を全部試したうえで判定する。
一時的に導線が見つけにくいのと、永久喪失は別物（2026-11-06 の査読で指摘）。

再発行の**競合で両方の資格情報が死ぬ**なら、それは恒久的喪失で所見。

## 使い分け

この7体は**初見**。毎回ゼロから始まり、過去の知見を持たない。

**蓄積型は別に要る。** 同じ製品を見続け、HANDOFF に残っている「なぜ見逃したか」を読んで
次に疑う場所を決める役。材料は既にある（「auth をまるごとモックしたから」
「スーパーユーザーで走らせたから」）。**初見には渡さない。**

メモリリーク・長時間フリーズの類は、20操作の探索では拾えない。
ソーク試験・プロファイラの領分である可能性が高く、Codex の調査結果を待って線を引く。
