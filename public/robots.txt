# TrustFlow — crawling policy
#
# This is a hint to well-behaved crawlers, NOT access control. The agreement
# screens are reached by holding a token, and a token in a URL is a credential:
# if one leaks, nothing here protects it. Revoking is what protects it —
# re-issue the counterparty's access, or let the 72-hour invite window close.
#
# Note what this file does NOT list. The app has no path router: every screen
# lives at `/` and is React state, so there is no /contract, /dashboard,
# /settings or auth callback path to disallow. The only crawlable surface that
# carries a credential is a query string, which is why the rules below are
# parameter patterns. `*` and `$` are part of RFC 9309 (section 2.2.3) and a
# conforming crawler supports them — an earlier version of this comment called
# them non-standard extensions, which was simply wrong. What remains true is
# that nothing here is enforcement: a crawler that ignores this file, or anyone
# the link was forwarded to, is unaffected, and a URL already indexed is not
# removed by adding a rule.

User-agent: *

# An invitation link and a re-issued access link. Both carry the credential
# itself in `?token=` / `?guest=`.
Disallow: /*?*token=
Disallow: /*?*guest=

# Everything else is public: the landing page, and whatever an agent should be
# able to read about what this service is. /llms.txt does not exist yet.
Allow: /llms.txt
Allow: /$
